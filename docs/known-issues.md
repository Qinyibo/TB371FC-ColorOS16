# 当前缺口与值得继续的方向

截至2026-10-30，v23最终ZIP已实机双清，首启和Magisk初始化后的正常重启均通过。用户在同一组运行代码上确认日常和连续打断可以用；仍有少量丢帧，不是所有场景都达到零掉帧。

## 后续性能工作怎样接续

先确认当前加载的SystemUI、framework、Launcher、ART及设置与v23一致，不把历史实验状态当现在。旧记录里的PID、TID、boot_id只能用来解释那次trace，不能硬编码到新机。

优先沿实际长帧：窗口relayout进入哪一个同步调用、谁持有WMS/AMS或ClassLinker锁、RenderThread是在Runnable还是dequeueBuffer等待、消费者何时释放。并行窗口查询是等待者的证据不等于它就是全局锁持有者。

做一次有明确机制的修改，按同类输入和实际响应对照。A/B工作量、温度、缓存和应用阶段不同就写清楚，不以低帧数、更少启动或较短录制制造改善。只要用户实际仍卡，就不能用局部平均值宣布问题解决。

## 已撤回路线的用途

GPU队列优先级、AS1、刷新率降到120、CFS强提权、固定绑核、ART后台GC延后、桌面手势重放、强制client合成等均见[性能记录](performance.md)。研究源码公开便于复查，不表示可以全装。不要把这些历史候选加入v23默认构建。

本轮没有证明“骁龙870硬件只能这样”。同样，也不承诺再堆参数一定能解决。当前保留可用版本，并把证据和未解决路径留给下一位维护者。
