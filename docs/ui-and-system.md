# 界面、键盘、投屏与其他系统支线

## 局部资源优先于全局密度补偿

早期遇到引导、设置、通知/控制中心、安全键盘尺寸不协调。全局密度同时影响应用逻辑尺寸和系统资源，改它可能让另一处重新不合适。早期408/字体0.9和后期460密度的现场应分开记录，不把一张截图上的参数当全项目恒定值。

v22b竖屏导航引导卡片裁切，最终只加w600dp-port的三项尺寸，原有11项资源覆盖保持。经典通知卡片与分离控制中心保留当时已接受的排版，v17修预装扫描时不把内容全部退回原版。

原生资源构建入口在[baseline/ui-resources](../baseline/ui-resources/)，签名从环境变量提供，不公开本地私钥。资源覆盖在指定供体上验证，不是跨版本RRO安装即适配。

## 安全键盘：绘图与点击区域一起修

实际改到InputService、键盘尺寸模型和COUIKeyboardView。要统一模型坐标、按键宽度/间隙、绘图和命中测试，不是只把视图拉大或写一个全局DPI。保留原键值/文本，横竖屏完整曾得到用户确认。

后来从实际v4产物与原始DEX导出[差异补丁](../baseline/security-keyboard/keyboard-width.patch)，包含主要三类修改及重编译差异；原厂APK与历史输出哈希在同目录。投放先扫描原签名应用，再用指定原生准备链路加载，不复用其他版本的OAT/VDEX。

## 投屏Surface与O+ Connect

投屏相关ODMF输入有明确SHA与单点Surface guard补丁，见[baseline/projection](../baseline/projection/)。早期模块的开机检查错误依赖尚未初始化的screen-group属性，后来改核对实际面板模式；原生迁移再把检查放进init/zygote前准备链路。

“投屏组件已加载”“电脑远桌能控制”“手机投屏第一帧正常”是不同验收。电脑远控曾被残留失效代理阻断，清除后用户确认搜索和控制恢复；手机真实第一帧、各种方向与输入仍不能拿这条反馈代替。

早期原生投屏与Zygisk组合出现启动失败，不能把旧候选当作未经试验再重复刷。晚绑定APK与框架重新扫描会影响桌面权限/加载状态，热重启图形栈并不等于正常重启验证。

## AI停用是明确组件范围

保留原AI transaction模块及脚本，早期记录为禁用七个组件。它不是清除所有应用内嵌AI，也不能把功能名叫“AI停用”当作全系统没有任何AI路径。恢复逻辑与组件清单在原生模块种子源码中。

## 隐私密码与人脸不是同一件事

隐私密码交付含本地gateway/controller、父进程终止包装和原生服务/策略投放；后端是上游公开预编译产物，本地只对独立服务/存储字面量做适配，不声称掌握完整后端源码或硬件TEE实现。来源说明和网关源码见[privacy](../privacy/)及模块NOTICE。

人脸早期完成过硬件授权验证器接入工厂/Session的离线候选和拒绝路径测试，但未证明完整HAL权限、合法录脸与解锁。这里保留研究历史，当前不标成已修好功能，不把编译成功、挑战值正常或接口可调用当实际认证成功。

## 当前“原生化”的准确含义

SystemUI触摸层补丁、窗口规则和B站宽度直接进ROM，不需要额外微信/B站模块。原生笔事件在framework/厂商应用中处理，init负责代码准备；通信后台由原init恢复。

同时v23仍通过原生module-delivery投放AI、前台调度、四扬和隐私密码四个既有模块，部分应用代码仍有受控绑定。这不是把整个系统变成无Root、无模块或纯源码AOSP。仓库把执行方式按组件分别说明，避免“原生化”掩盖真实依赖。
