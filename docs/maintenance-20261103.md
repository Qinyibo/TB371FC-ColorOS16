## 两项严重问题

1. **USB／fastboot 未修复。** 两个 64 KiB 验证镜像可刷入，96 MiB boot 在下载阶段仍发生错误 121，未进入该次 boot 写入。Android 与原厂 4.19.157 Recovery 下的随机数据读取也失败。验收必须使用正式脚本，经 bootloader fastboot 完整刷入当前 ROM 并正常开机。
2. **偶发黑屏无法唤醒未根治。** 现场有触控初始化 INIT=0x9D、固件硬复位重试失败及反复显示启用失败。r104 仅允许已有死屏供电恢复路径穿过 keep-panel-power 判断，不构成初始化根因修复或异常恢复成功证明。

USB 当前按用户要求暂缓，等待改变连接环境；黑屏等待自然复现和用户反馈，不反复进行唤醒压力测试。现有证据不能确定 USB 故障来自电脑端、连接链路或平板端，没有判定数据线损坏。

## 当前保留的改动

- 音频：保存与当前 API19 配套一致的扬声器 Java/JNI 和构建脚本，内核修正实际 session/COPP 的 DSP 混音器更新与应答处理。
- 系统服务：无线诊断按需启动、工厂服务启动规则、恢复通信后台原有 oneshot 行为、充电 V3 查询兼容。
- 动画：出厂默认等级由被覆盖的 2 修正为 4；保存已使用的设置／桌面／负一屏生成源码与覆盖层；通用取消动画按实际任务编号返回截图。
- 冻结：HANS 未就绪时交还 Android 缓存冻结；r103 修正 ptrace 暂停与冻结交叠时 SIGKILL 退出无法完成的问题。
- 电池：r102 在 battery 接口提供与瞬时电流相同方向约定的平均电流，保留原始 BMS 与充电控制逻辑。
- 发布输入：v25/v26 的镜像构建、回读、打包脚本；v26 移除六项推广预装，保留现有分区布局和原刷机入口。

内核提交链从 `ad9987077d8eb726a1be70801a2b7aa12e886b54` 到 `455927db6665e2b3696aa8a96bc97fb09c20bd3a`。实际配置、工具链与本地源码记录见内核仓库 `build/tb371fc/`；内核变更摘要见该仓库 `docs/tb371fc/maintenance-20261103.md`。
