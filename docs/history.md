# 版本沿革：哪些是发布包，哪些只是试验

## 早期：R7/R93基础到R94的八项修复

10月上旬的工作并非只在调性能，还同时处理引导/设置/控制中心尺寸、安全键盘、AI组件、通信共享、人脸、亮屏、投屏和四扬方向。早期稳定现场曾是 #11 内核、408密度、0.9字体；这组数值是历史状态，不能覆盖后来460密度的现场，也不是v23的统一推荐。

早期已有安全键盘横竖屏完整、搜索胶囊和布局保持的用户反馈。通信和人脸则曾长期只有可编译候选，未完成真实设备流程；它们不能因为代码目录存在就写成“全功能修复”。投屏与Zygisk组合曾有启动检查失败，恢复原R93后才继续；这段教训后来促成了减少晚绑定组合、按原生启动链路整合的方向。

## 10月18日：v16事故与v17交付

v16双清后出现黑背景、状态栏和手势不可用。原因不是普通动画参数，而是预装SystemUI缺少包管理器所需的APK v2签名容器，首次扫描没有正常登记SystemUI。已有系统上的临时替换测试漏掉了这一点。

v17恢复可扫描的原有签名容器，保留当时的通知卡片内容和原生库对齐。修复版候选经过两次原CMD双清、手势/通知/控制中心和重启检查。最终双窗种子合入又做了镜像回读与校验，但当时没有把最后一份ZIP重新双清一遍。这个范围差别必须保留。

上次真正公开分发的基准是：

```
ColorOS16_TB371FC_R94T_v17_20261018_TEST.zip
7141210126 bytes
SHA256 4740d139e6694ea1e1e291e11542bedaf2171d73403c8219668f0a9da7805eac
```

当时记录保留 #38 内核、HWC/WLAN适配、四扬0.25、AI停用和前台调度。B站9.15.0用原版APK，加入可拖动双窗和直播例外，尚没有后来首页缩窄。

## 10月20—21日：#43与笔、通信链路

#43建立在4.19源码和原配置上，重点合入触控/DSI唤醒、IRQ wake所有权、Hall/PM同步、USB兼容与音频路由相关修改。它不是升级到5.10/6.1。构建过程中使用临时bind覆盖源码，编完恢复底树；开源时必须把真正参与构建的覆盖文件合进源码，不能只上传恢复后的底树。

10月21日的笔/通信专项曾在 #39 现场部署：修复笔首次生成、现代BLE回调与CTN730事件链；通信中心去掉oneshot后，受控退出约3.11秒可恢复。那轮没有真实手机和笔，不等于所有硬件功能通过。

## 10月24—25日：v22、v22a、v22b是私测沿革

这几个名字用于后续原生交付、首启和相机试验，不是用户所指的“上次公开v17”。主要推进原生笔投放目录/标签、准确的框架校验、引导竖屏资源、相机系统基座和完整包首启。

v22b后来实际用原CMD清空刷入，#43、原生组件生成、相机v7、普通相机API及有限旋转/熄亮屏检查通过。相机v8曾单独装机对照前摄默认HIGH录像，封存v22b ZIP仍为v7。v23确认沿用v7，不把历史v8试验混写成已交付内容。

## 10月25—30日：流畅度试验与撤回

主诉逐渐集中到应用冷启动、快速上滑打断和动画掉帧。试过前台CPU份额、GPU调频队列、GPU最低频、AS1、刷新率、锁调度兼容、CFS优先级、绑核、ART后台GC延后、桌面手势重放和强制client合成等。

其中一些能改善某个局部计数器，却没有稳定的整段收益；有的还出现实际操作覆盖减少。最终没有把这些新试验合成一个“性能大礼包”。保留的是用户明确反馈有效的400ms触摸层延后/失焦取消、关闭自动分屏推荐、原生窗口规则及B站首页宽度。原Launcher和ART恢复。

## 10月30日：v23最终包

相对私测v22b，最终改动分布在system、system_ext和vendor：原生SystemUI补丁、B站框架宽度、微信/B站规则、启动脚本及两层校验列表、一次性桌面编译，以及vendor里初始化服务的运行域。

第一轮清刷发现：Magisk环境初始化后，旧 `u:r:ksu:s0` 不再有效，正常重启时r91-rom服务在执行脚本前就退出。改用已存在的 `u:r:magisk:s0` 后重新打完整包，再实际双清并复核首启、正常重启。最终ZIP不是仅离线核验过的拼装结果。

用户在同一组最终运行代码上反馈日常和连续打断正常可用；采样仍有少量丢帧。这是当前发布依据，不是硬件上限、零掉帧或所有历史问题根治的结论。

最终包及哈希见[v23验收](../release/v23/TESTING.md)。上述日期按项目材料归档日期；早期设备日志因双清时间尚未同步，可能显示2025-01-01，不据它重新排列版本顺序。
