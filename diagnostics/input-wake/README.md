# 本地24小时只读监控（不调用AI）

这是独立Python程序，不调用模型/API，不消耗持续token。`supervise_24h.py` 在电脑后台管理 `monitor_24h.py`，最多24小时自动结束；临时阻止电脑自动睡眠，结束释放，不改Windows长期电源策略，电脑屏幕可熄灭。

```text
python supervise_24h.py --adb <adb.exe> --serial <设备序列号> --out <不存在的电脑目录>
```

## 实际做什么

- 持续保存main/system/events/crash到电脑的256MiB环形文件；断线自动续接，采集进程退出后本地监督程序重启它，旧数据保留在原run目录。
- 每5秒读取触控状态、IRQ计数、boot ID及SystemUI PID；亮屏约10秒、休眠约30秒保存input/window/power/桌面手势服务。近期60份快照滚动保留。命令耗时会使实际间隔增加，不承诺逐帧覆盖。
- SystemUI死亡、触控failed进入1、设备boot改变、ADB断线时自动保存事件：最近两个日志分片、12份前序快照、即时完整快照和约30秒后的日志/状态。**采完继续运行**，不会像旧工具第一次事件后退出。
- 自动事件最低间隔60秒，每个运行段上限16组，避免故障循环耗尽磁盘；之后仍保存环形日志/近期状态。用户手动抓取不受该冷却/自动上限约束。
- 输出目录双击 `capture-now.cmd` 可手动抓取，双击 `stop.cmd` 停止整项任务；也可在该目录建立capture-now/stop文件。监督程序转交给当前run，不依赖AI在线。

## 边界

不按键、不注入触摸、不主动亮灭屏、不重启服务或平板、不刷写、不修改属性/日志开关/分区。读取日志和状态有开销，连接USB及周期读取可能改变休眠条件，不能把这一环境当离线续航验收。

不是保证抓到每次故障：断线期间无法取数据，未输出的debug信息无法保存，瞬态可能短于采样间隔；物理黑屏/单指被吞未必触发自动规则。用户报告异常后仍应立即标记。电脑关机、注销/人为结束程序、存储耗尽等也会中断。

原始数据含应用/设备信息，只存本地，不自动上传。至少3GiB可用空间；日志滚动、快照和自动事件均有单运行段保留上限。

## 已验证到哪里

`python -m unittest test_monitor_24h.py -v`：环形覆盖不破坏冻结证据、真实事件字符串/状态转换、Windows状态读锁不终止记录。

本次启动时还执行了一次**采集器只读自检**（collector_self_check）：即时7项读取返回0，30秒后资料完成，采集仍继续；没有制造平板故障。监督程序的采集子进程退出/续启也在电脑端验证。它们验证采集机制，不证明黑屏/触控根因修复，也不代表24小时已经跑完。
