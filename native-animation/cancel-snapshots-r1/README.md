# 取消动画的任务截图对应关系修正

`RecentsController.getSnapshotsForPausingTasks()` 原代码始终读取第一个任务，且没有填充任务编号数组。桌面直接将这些编号作为截图表的键，导致单任务得到键 0、多任务重复首项。

修正仅将 `mPausingTasks.get(0)` 改为 `get(i)`，并在截图前写入 `taskIds[i] = taskId`。保留原有空列表、RemoteException、截图为空和取消通知处理。不是应用白名单，也没有新增超时或动画补偿。

构建：`python build.py <精确原版 SystemUI.apk> <新输出目录>`，使用本机 Android SDK 36、Java 21 与 dexlib2 3.0.3。输入必须为 SHA256 `56bc35af0c908ec00151ec792f3df048985d1cf0db06260b6a86f42614d76928`。

已检查所有方法的指令语义，只有目标方法改变；APK 仅 classes4.dex 改变，原签名块和原生库对齐保留。原 APK 本身已经过修改，保留签名块不等于完整签名验证通过。

已在平板 ART 执行原方法与候选方法的隔离测试：原版返回任务 0，候选在空、单任务、二任务和三任务下正确返回编号。测试使用真实 ATMS 调用，但当时所有任务快照为空，因此不能冒充有图像的端到端截图验收。

2026-11-03 已集成 v26/r104 的 system_ext 镜像，完成保留数据升级、分区回读和实际重启核对。实机 APK SHA256 为 `8ad70cc761213ed3854650f1f477a010fb443b39f96c48c0de62c347f2f39b4a`，无临时 SystemUI 文件挂载，进程已映射镜像中的 APK。回退使用电脑保留的 v25 包或已核验的静止 super 备份；仍未证明消除用户反馈的黑条。

用户要求黑条自行手测，已停止黑条实机测试。本修正纠正了通用取消动画的真实错误，尚未证明消除反馈中的黑条。不能将其写成黑条已修复。
